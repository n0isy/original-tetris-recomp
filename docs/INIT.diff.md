# `$INIT`: что именно отличается от нужного

Оба листинга прочитаны целиком. Смещения — **от начала модуля**.

* `INIT-ours.asm` — наш `$INIT`, база `001520`, размер `0o714` (460 б), 148 команд
* `INIT-tetris.asm` — `$INIT` внутри `TETRIS.SAV`, база `017252`, размер `0o1044` (548 б), 183 команды

Нужный **на 88 байт длиннее**. Это не оптимизатор переходов (тот только
укорачивает) и не патч — это другая редакция модуля. Ниже все расхождения.

---

## Совпадающий костяк

Начало идентично команда в команду до `+0034`:

```
+0000  TST <ячейка>        ; занята ли точка перезапуска
+0004  BNE ...             ; занята -- перейти к завершению
+0006  JMP <завершение>
+0012  JMP @<ячейка>
+0016  BR  +0000
+0020  $START: CMP #14,#14 ; <<< ТОЧКА ВХОДА ПРОГРАММЫ, сверка $VER
+0026  BEQ <дальше>
```

И совпадает вся середина — построение двух файловых блоков (терминал на ввод и
на вывод) с `+0130` по `+0306`: те же `MOV R5,(R0)+`, `MOVB #40,(R5)`,
`ADD #20,R5`, `MOV #4210,(R0)+`, `MOV #100220,(R1)+`, `MOV #77150,(R0)`, цикл
`CLR (R0)+ / CLR (R1)+` на 4 оборота, `MOV #4377`, `MOV #4777`.

## Расхождение 1. Печать диагностики: `EMT 351` против своей подпрограммы

```
        наш                              тетрис
+0030   MOV #<строка>,R0                 MOV #<строка>,R0
+0034   EMT 351          <<<             JSR PC,<печать строки>   (+0034)
+0036   BISB #10,53      <<<             BIS #10,53               (+0040)
+0044   EMT 350                          EMT 350                  (+0046)
```

`EMT 351` — это `.PRINT` монитора. В нужной сборке вместо него вызов
собственной подпрограммы (см. расхождение 5), а установка бита в слове `53`
делается словной операцией `BIS`, а не байтовой `BISB`.

**Почему так.** Диагностика печатается тогда, когда программа уже сломана.
Своя печать через `EMT 341` (`.TTYOUT`, посимвольно) не зависит от состояния
монитора, а `.PRINT` — зависит.

## Расхождение 2. Резерв памяти под USR, `+0074` (−8 байт у них)

```
        наш                              тетрис
+0072   EMT 354                          EMT 354
+0074   MOV R0,<верх>    <<<             MOV R0,SP                (+0076)
+0100   SUB #214,R0      <<< НЕТ У НИХ   MOV R0,<яч.1>            (+0100)
+0104   MOV R0,SP                        MOV R0,<яч.2>            (+0104)
+0106   MOV R0,<яч.1>                    CLR <яч.3>               (+0110)
+0112   CLR <яч.3>                       CLR <яч.4>               (+0114)
+0116   CLR <яч.4>                       CLR <яч.5>               (+0120)
+0122   CLR <яч.5>                       MOV <верх>,R5            (+0124)  <<<
+0126   MOV R0,R5        <<<             MOV R5,<яч.6>            (+0130)
```

Два отличия рядом:

* у нас `SUB #214,R0` — под вершиной памяти резервируется **140 байт**
  (область USR), у них не резервируется ничего;
* мы берём начало кучи из регистра (`MOV R0,R5`), они — из ячейки
  (`MOV <верх>,R5`).

## Расхождение 3. Начало кучи, `+0312`

```
        наш                              тетрис
+0312   MOV <ячейка>,R5  <<<             ADD #100,R5              (+0312)
+0316   MOV R5,<яч.7>                    MOV R5,<яч.7>
+0322   MOV R5,R0                        MOV R5,R0
```

У нас указатель перечитывается из ячейки, у них — сдвигается на `0o100` от
текущего. Разные соглашения о том, где кончаются файловые блоки.

## Расхождение 4. Лишний вызов `EMT 374`, `+0416` (−8 байт у них)

```
        наш                              тетрис
+0406   BEQ +0420                        BEQ +0416
+0410   MOV #177777,<яч.8>               MOV #177777,<яч.8>
+0416   BR +0426         <<< НЕТ У НИХ
+0420   MOV #1417,R0     <<< НЕТ У НИХ   ---
+0424   EMT 374          <<< НЕТ У НИХ
+0426   MOV <ввод>,-(SP)                 MOV <ввод>,-(SP)         (+0416)
+0432   MOV <вывод>,-(SP)                MOV <вывод>,-(SP)        (+0422)
+0436   JMP $BEGIN                       JMP $BEGIN               (+0426)
```

Мы перед передачей управления программе делаем ещё один `EMT 374`; в нужной
сборке этого нет.

## Расхождение 5. Обработчик ловушек переписан целиком

Это и есть источник лишних 88 байт. У нас обработчик **зовёт `$ERROR`**
(паскалевский обработчик) со встроенным описанием; у них он печатает сам.

### У нас, `+0474`..`+0622`

```
+0474  BCC ...
+0476  TST <яч.9>
+0502  BEQ ...
+0504  MOV #<блок>,R0
+0510  MOV #1400,(R0)
+0514  MOV #<адрес>,2(R0)
+0522  EMT 375
+0524  JMP @<яч.9>
+0530  MOV (SP),<яч.10>
+0534  JSR R0,$ERROR        ; класс 0, номер 0, длина 11, "TRAP TO 4"
+0556  MOV (SP),<яч.10>
+0562  JSR R0,$ERROR        ; класс 0, номер 0, длина 31, "RESERVED INSTRUCTION TRAP"
```

### У них, `+0550`..`+0654`

```
+0550  MOV R0,-(SP)
+0552  MOV #<"TRAP TO 4">,R0
+0556  BCC ...
+0560  MOV #<"RESERVED INSTRUCTION TRAP">,R0
+0564  TST <яч.9>
+0570  BEQ ...
+0572  MOV #<блок>,R0
+0576  MOV #1400,(R0)
+0602  MOV #<адрес>,2(R0)
+0610  EMT 375
+0612  MOV (SP)+,R0
+0614  JMP @<яч.9>
+0620  EMT 355                    ; сбросить очередь вывода
+0622  JSR PC,<печать строки>     ; сам текст ловушки
+0626  MOV #<" - FROM PC ">,R0
+0632  JSR PC,<печать строки>
+0636  MOV 2(SP),R0               ; адрес возврата
+0642  JSR PC,<печать числа>      ; шестизначное восьмеричное
+0646  MOV #<перевод строки>,R0
+0652  JSR PC,<печать строки>
```

Отсюда и дополнительный текст в нужной сборке: `RESERVED INSTRUCTION TRAP`,
`TRAP TO 4`, ` - FROM PC ` лежат отдельными строками, а не как аргументы
`$ERROR`.

## Расхождение 6. Две подпрограммы печати в хвосте, `+0740`..`+1042`

У нас их нет вовсе. У них:

```
+0740  печать строки:
         MOV R1,-(SP)
         MOV R0,R1
   цикл: MOVB (R1)+,R0        ; ASCIZ
         BEQ конец
   ждём: EMT 341              ; .TTYOUT
         BCS ждём
         BR цикл
   конец: MOV (SP)+,R1
         RTS PC

+0762  печать шестизначного восьмеричного:
         MOV R1,-(SP) / MOV R2,-(SP)
         MOV R0,R1 / CLR R0
         ASL R1 / ROL R0            ; первая цифра -- 2 бита
         MOV #6,R2                  ; всего 6 цифр
   цикл: CLR R0
         ASL R1 / ROL R0            ; дальше по 3 бита
         ASL R1 / ROL R0
         ASL R1 / ROL R0
         ADD #60,R0                 ; в код цифры
   ждём: EMT 341
         BCS ждём
         DEC R2 / BNE цикл
         MOV (SP)+,R2 / MOV (SP)+,R1
         RTS PC
```

Обе — чистый ассемблер поверх `.TTYOUT`, без участия рантайма.

## Итог

| расхождение | байт |
|---|---|
| 1. `EMT 351` -> вызов своей печати, `BISB` -> `BIS` | 0 |
| 2. нет `SUB #214,R0`, иначе берётся начало кучи | −8 |
| 3. `MOV <яч>,R5` -> `ADD #100,R5` | 0 |
| 4. нет `BR` + `MOV #1417,R0` + `EMT 374` | −8 |
| 5. обработчик ловушек переписан, печатает сам | +36 |
| 6. добавлены две подпрограммы печати | +68 |
| **итого** | **+88** |

`0o714 + 88 = 0o1044` — ровно размер `$INIT` в тетрисе. Список полон.

## Проверка каждого утверждения

Не на глаз: поиск точных последовательностей слов в обоих образах.

| признак | у нас | в тетрисе |
|---|---|---|
| `SUB #214,R0` (резерв под USR) | 1 | **0** |
| `EMT 351` (`.PRINT`) | 1 | **0** |
| `EMT 374` | 1 | **0** |
| `EMT 355` | **0** | 1 |
| `BISB #10,53` (байтовая) | 1 | **0** |
| `BIS #10,53` (словная) | **0** | 1 |
| `JSR R0,$ERROR` | 2 | **0** |
| `EMT 341` (`.TTYOUT`) | **0** | 2 |
| печать строки: `MOVB (R1)+,R0` / `BEQ` | **0** | 1 |
| печать числа: `ASL R1` / `ROL R0` | **0** | 4 |

Два `JSR R0,$ERROR` у нас — это ровно две ловушки (`TRAP TO 4` и
`RESERVED INSTRUCTION TRAP`), которые в нужной сборке печатаются своими
подпрограммами; четыре пары `ASL/ROL` — один сдвиг на 2 бита плюс три по
3 бита в цикле шестизначной печати.

Совпадение общего костяка, по байтам вне релокаций:

* начало модуля `+0000..+0033` — **18 из 20** (расходятся два байта константы
  `$VER`, которую подставляет компоновщик);
* построение файловых блоков `+0130..+0307` — **100 из 100, то есть целиком**.

Итого: описание подтверждено полностью, размеры сходятся (`0o714 + 88 = 0o1044`).

## Вывод: правкой не обойтись

В `$IO` три точечные правки, и его можно довести. `$INIT` — другая редакция:
переписан обработчик и добавлены подпрограммы. Разумнее не править наш, а
**восстановить нужный прямо из `TETRIS.SAV`**, где он лежит целиком по
`017252..020315`.

Задача сводится к тому, чтобы отличить в этих 548 байтах адреса от констант:
слово считается адресом, если его значение попадает в диапазон известных
модулей или области данных `RTSDAT` (`031602..032415`). Проверка точная:
восстановили модуль -> слинковали -> сравнили с оригиналом побайтово.

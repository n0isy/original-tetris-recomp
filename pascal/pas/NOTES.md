# GAME.PAS восстановлен: тетрис собирается из Паскаля побайтово

    ./pascal/pas/build.py
    различий: 0
    md5 наш      49d72cad48c6b34aa7f56cc4fe032622
    md5 оригинал 49d72cad48c6b34aa7f56cc4fe032622

`GAME.PAS` -- 589 строк. Цепочка подлинная: PASCAL -> MACRO -> LINK в
эмуляторе; из паскалевской сборки берётся объектный модуль игры, рантайм
подставляется наш восстановленный. На ассемблере в исходнике ровно то, что
было на нём у автора: `KEYIN` (опрос клавиатуры без ожидания), `WAIT`
(задержка по регистру терминала), чтение клавиши в `KEY`, `BIS #10100,@#44`
и слив очереди ввода -- всё через `(*$C ... *)`.

## Ассемблерные вставки -- все семь мест

| адрес | где | что делает |
|---|---|---|
| `001000..001040` | `KEYIN` -- всё тело | ждать клавишу, считая обороты опроса `.TTYIN`; счётчик в своём слове `DELAY`; слить очередь |
| `001064` | `RANDOM`, первая строка | `MOV DELAY,SEED(6)` -- счётчик времени раздумья -> локальная `SEED` |
| `001206` | `RANDOM`, перед концом | `MOV SEED(6),DELAY` -- зерно сохраняется между вызовами |
| `001454` | `SCORES`, перед `read(NAME)` | слить накопившиеся нажатия |
| `003046..003076` | `WAIT` -- всё тело | задержка `PAU x TCK` оборотов по регистру терминала `177564` |
| `012526..012540` | `KEY` | взять клавишу не дожидаясь; буфер пуст -- `C` остаётся `CHR(0)` |
| `016672` | главная, перед циклом партии | `BIS #^O10100,@#^O44` -- неблокирующий `.TTYIN` и режим без эха |
| `017026` | главная, после звонка | слить нажатия до вопроса «ЕЩЕ ПАРТИЮ?» |

Все вставки об одном: клавиатура без ожидания и точное время -- две вещи,
которых в этом Паскале нет. Компилятор подставляет в текст вставки смещения
паскалевских имён (`C(6)` -> `0(SP)`, `@PAU(6)` -> `@6(SP)`), поэтому вставки
переживают перестановку локалов. `EMT ^O340` -- это `.TTYIN`; после вставки с
JSW он неблокирующий, отсюда идиомы `BCS 1$` «ждать» и `BCC 1$` «слить».

# Как это восстанавливалось (заметки по ходу)

Цель -- исходник на ПАСКАЛЕ, из которого цепочка `PASCAL -> MACRO -> LINK`
даёт те же 13824 байта. Критерий побайтовый, как и раньше: компилятор у нас
есть и он детерминирован.

## Компилятор тот самый

`pascal/gold/PASSIM.SAV` печатает `$VER=12.` -- десятичное 12, восьмеричное
`14`. Ровно то, что стоит в игре. Значит версия совпадает.

Запуск: `./tools/pasbuild.py <файл.pas> ИМЯ -o <каталог>`; забирает `.MAC`,
`.OBJ` и `.SAV`.

## Директивы, а не ключи командной строки

Режимы задаются прямо в тексте, комментарием. Найдено в `pascal/gold/*.PAS`:

| директива | что делает | где подсмотрено |
|---|---|---|
| `(*$T-*)` | снять контроль переполнения стека | `ERROR.PAS`, `INTRPT.PAS` |
| `(*$A-*)` | снять контроль границ массивов | `PASPRF.PAS` |
| `(*$E+*)` | внешнее определение процедуры | `ERROR.PAS` |
| `(*$X+*)` | расширенная точность | `PASPRF.PAS` |
| `(*$C ...*)` | **вставить строки прямо в текст MACRO** | `INTRPT.PAS` |

Проверено опытом: с `(*$T-*)` из вывода исчезает `JSR %7,$B127`. `$B127` --
это проверка запаса стека в 36 байт (`$REG+14`), в игре её нет. Границ
массивов игра тоже не проверяет, значит `(*$A-*)`.

`(*$C*)` подставляет в ассемблерные строки **имена паскалевских переменных**:
в `INTRPT.PAS` пишут `VECTOR(6)`, `PROTFAIL(6)`, и компилятор заменяет их
смещениями. Этим же способом в игру попал `KEYIN`: он лежит первым в модуле,
до всех процедур, и обращается к параметру через `@2(SP)`.

## Как выглядит вывод компилятора

`.RADIX 10`, регистры числами: `-(6)` это `-(SP)`, `%5` это R5, `%7` это PC.
Меток на близких переходах нет -- пишется `.+6`.

Пролог главной программы, слово в слово как в игре:

```
	MOV	#<размер>,-(6)
	JSR	%7,$B70
	MOV	(6)+,%5
	MOV	(6),(5)+		; блок файла INPUT
	MOV	2(6),(5)+		; блок файла OUTPUT
	MOV	%5,$RESR5
```

Строковые константы -- `.WORD` десятичными, с завершающим `.WORD 0`; отсюда
хвостовые нули после каждой строки. **Литерал кладётся в конец той процедуры,
где встретился**, поэтому одинаковые строки лежат в файле по нескольку раз.

Процедуры выводятся в порядке объявления, тело программы последним.

Узнаваемые формы:

| конструкция | во что превращается |
|---|---|
| `for i := a to b` | `MOV #a,-(6)` `MOV #b,-(6)` `MOV 2(6),@4(6)` / `CMP @4(6),(6)` `BLE .+6` `JMP кон` ... `INC @4(6)` `BVS .+6` `JMP нач` |
| `while c do` | `CMP ...` `Bxx .+6` `JMP кон` |
| `repeat ... until c` | тело, потом `Bxx .+6` `JMP нач` |
| `if c then ... else` | `TSTB` `BNE .+6` `JMP иначе` ... `JMP конец` |
| вызов процедуры | параметры на стек, `JSR %7,Lн` |
| вызов функции | `CLR -(6)` под результат, потом параметры |
| процедура с локальными | `SUB #n,%6` или `CLR -(6)`, `JSR %0,$B74` если нужны регистры |
| `x * 2` | `ASL` -- степени двойки сворачиваются |

## Раскладка глобальных переменных -- восстановлена точно

Область = 4 байта (блоки файлов `INPUT`/`OUTPUT`, их кладёт пролог) плюс
переменные. `integer` выравнивается на чётный адрес, `char` и `boolean`
занимают байт, `packed array` выравнивается на слово.

У игры `MOV #2222,-(SP)` -- восьмеричное, это 1170. Значит под переменные 1166
байт. Блок ниже даёт **ровно 1170**, и все проверенные смещения совпадают с
теми, что стоят в `GAME.MAC`:

```pascal
(*$T-,A-*)
var
  NXT   : array[1..19] of integer;                   (*   0 *)
  SHAPE : array[1..19] of record
            DX, DY : array[1..4] of integer
          end;                                       (*  38 *)
  CUR   : integer;                                   (* 342 *)
  WELL  : array[0..11] of array[0..21] of char;      (* 344 *)
  ERAP  : integer;                                   (* 608 *)
  DRWP  : integer;                                   (* 610 *)
  ERASE : array[1..5] of packed array[1..6] of char; (* 612 *)
  DRAW  : array[1..5] of packed array[1..6] of char; (* 642 *)
  PAUSE : integer;                                   (* 672 *)
  CURPC : integer;                                   (* 674 *)
  NXTPC : integer;                                   (* 676 *)
  SHOWN : boolean;                                   (* 678 *)
  XPOS  : integer;                                   (* 680 *)
  YPOS  : integer;                                   (* 682 *)
  LANDED: boolean;                                   (* 684 *)
  TICKS : integer;                                   (* 686 *)
  FILLER: packed array[1..42] of char;               (* 688 *)
  LEVEL : integer;                                   (* 730 *)
  SCORE : integer;                                   (* 732 *)
  ESCCH : char;                                      (* 734 *)
  FILLCH: char;                                      (* 735 *)
  PAD2  : packed array[1..2] of char;                (* 736 *)
  ANS   : char;                                      (* 738 *)
  PAD3  : packed array[1..2] of char;                (* 740 *)
  LINES : integer;                                   (* 742 *)
  QUOTA : array[0..9] of integer;                    (* 744 *)
  PAD4  : integer;                                   (* 764 *)
  HIGH  : array[1..20] of record
            NAME : packed array[1..16] of char;
            LVL, SCR : integer
          end;                                       (* 766..1165 *)
```

Как читались смещения:

* **19 фигур.** База `SHAPE` вычислена из `R5+16i+22`: при индексе с единицы
  это 38. Конец массива упирается в `CUR` по 342, значит элементов ровно
  `(342-38)/16 = 19`. И это не случайность: 1+2+2+4+4+4+2 = 19 -- столько
  различных положений у семи тетромино, если не хранить повторы. Массив `NXT`
  по смещению 0 связывает их в кольцо поворотов.
* **Стакан** -- байт на клетку, строка 22 байта (множитель `#26` в
  `JSR PC,$B116`), 12 строк: пол лежит по `1112(R0)` = 344+11*22.
* **`ERASE`/`DRAW`** -- по пять шестибайтовых групп `ESC Y строка столбец c c`.
  `SETUP` кладёт в них `0o54400+ESC` (то есть `ESC` и `Y`), `0o27040` (` .`) и
  `0o56533` (`[]`). Отсюда и `MOV #36,-(SP)` -- 30 символов за один `$B32`.
  `ERAP` и `DRWP` держат их адреса.
* **Таблица результатов** -- 20 записей по 20 байт: имя 16 символов, потом
  уровень и счёт. Видно из `MOV #24,-(SP)` (восьмеричное 20) и `MOV #12,R2`
  (10 слов при копировании).

Не опознаны: 42 байта по 688, по два байта на 736 и 740, и слово на 764.
Размер известен точно, назначение нет.

## Разгаданное на финишной прямой

* **`@` существует**: `P := @G` законен и даёт `MOV R5,R0; ADD #off,R0`.
  Панели стирания/рисования -- вариантная запись (массив групп / строка 30),
  указатели на неё лежат в глобалах, печать -- `write(ERAP^.S)`.
* **`EXIT` -- выход из цикла**, не из процедуры: разматывает блок цикла
  константой (`ADD #6,SP`) и прыгает за цикл. Голый `EXIT` вне цикла -- ошибка.
* **`goto` вперёд** идёт через `R4`: `MOV #глубина,R4; JMP метка`, а у метки
  преамбула `ADD R4,SP`, обходимая в обычном потоке. **Назад** -- простой JMP.
* **Массив-в-массив и запись-в-запись** копируются циклом `MOV (Rs)+,(Rd)+`
  со счётчиком в первом свободном регистре; сложный адрес считается первым.
* **Индексация масштабируется** `$B116` (беззнаково) для размеров не-степеней
  двойки и сдвигами для 2/4/8/16; это не зависит от типов в исходнике.
* **`X - конст` -> `ADD #-конст`**, но `ORD(ANS) - ORD('0')` -> `SUB #60`:
  свёрнутая функция от литеры не превращается в отрицательную добавку.
* **`A[i].F := A[i].F + (выражение)`**: адрес элемента-слагаемого считается до
  выражения, само сложение -- `ADD elem(Rн),Rакк`. Без скобок порядок другой.
* **Лесенка `MOV (R4),R4` перед вложенной процедурой** -- входы для вызовов с
  большей глубины: длина = 11 минус лексический уровень.
* **`C := CHR(0)`** для локала со смещением 0 -- `CLRB @%6` (одно слово).
* **Загадка девяти слов `011404`** решена: это та самая лесенка у `ROTATE`.

## Разгаданное на ходу

**Знаковость решает всё.** `integer` даёт `$B78/$B80/$B82` -- умножение и
деление с контролем переполнения. Тип `0..65535` даёт `$B116/$B118/$B120` --
без контроля. Подтип `0..32767` не годится: он всё ещё знаковый. Именно
беззнаковый тип стоит в игре везде, где идёт счёт и индексация.

**`mod` на степень двойки** превращается в маску через регистр:

```
	MOV 	(6)+,%0
	BIC 	#32768,%0
	MOV 	%0,SEED(6)
```

а `and` -- в маску прямо на стеке. Эти две формы и различались в `RANDOM`.

**Восьмеричное в тексте на ПАСКАЛЕ надо писать десятичным.** `0o31425` = 13077.
В ассемблерных вставках наоборот -- `^O340`.

**Строка может переноситься через конец строки исходника.** Литерал `'<CR><LF>'`
записан буквально: кавычка, перевод строки, кавычка. Компилятор принимает и
выдаёт `.WORD 2573`.

**Локальные метки MACRO `n$` живут только между глобальными.** `BR 3$` через
`DELAY:` собирается как `BR .` -- нужны обычные имена.

**Присваивание записи целиком требует именованного типа**, иначе
`INCOMPATIBLE TYPE`. Отсюда в исходнике был раздел `type`.

**Вложенные процедуры получают кадр объемлющей в `R4`.** `ROTATE` пишет в
локальную переменную `SETUP`, значит объявлена внутри неё -- оттого и стоит в
модуле раньше.

**Пропуски в объектнике.** 18 байт по `003114` заполнены `011404`; объектный
файл их не задаёт, в `.SAV` там осталось содержимое буфера компоновщика.

## Чего ждать

Имён переменных, имён процедур и комментариев в выводе компилятора нет -- есть
`L1`, `L2`, `L3`. Побайтовое совпадение докажет структуру: типы, порядок
объявлений, вложенность, форму каждого цикла и условия. Но не то, как автор
всё это называл.
